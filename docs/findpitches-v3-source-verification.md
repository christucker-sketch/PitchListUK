# V3 discovery and source proof

Discovery receipts remain immutable inputs, including their original producer ID, market, URLs, extracted fields and content hash. A discovery classification such as `OPEN_NOW` is insufficient for readiness. Verification fetches the retained original source directly, records an immutable bounded source document, and adds a separate versioned proof receipt. This path contains no Serper call.

`source_documents` retains the fetched HTML or failure, redirect chain, timestamp and content hash. `source_verifications` retains the entity revision, document reference, verifier version, facts, reasons and expiry. Update, delete and replacement guards protect both tables. Each proof expires within 24 hours, or at an earlier application deadline. A changed entity revision invalidates proof; unchanged producer replay cannot refresh it. Older proof cannot supersede a newer receipt.

The enrichment queue verifies new or changed shadow discoveries before readiness. It processes one durable job per tick, retains fetch failures as uncertainty, and uses existing queue retry/backpressure controls. Operators can recheck an existing shadow entity through authenticated `POST /verification/verify` on the enrichment Worker with `{ "entity_id": "..." }`. The endpoint derives the URL and proof itself; it does not accept caller-supplied verified claims. The ingest token cannot invoke it. `/verification/document` is an operator-only source-inspection helper.

| Source family | Verification behaviour |
|---|---|
| Eventeny | Requires an exact vendor ID and vendor-scoped offer, event JSON-LD, explicit source country, venue, organiser and calendar dates. Duplicate JSON-LD blocks with matching calendar facts are deduplicated despite timezone offsets. Conflicting events, editions, deadlines or states are held. An in-stock current offer window and application control can prove an open route. A TBA venue, cancellation, stale edition, waitlist or closed control prevents readiness. |
| LocalStalls | Requires an event-detail path, matching event JSON-LD/main heading, explicit address country and dated event. Uses the event's `Submit Application` control with an application UUID/event UUID and explicit stallholder-open state. Navigation, related events and footer vendor registration are excluded. Visible dates without a year do not acquire an inferred year. |
| UKCraftFairs | Requires a numbered event-detail path and scoped single-event proof. Contact-organiser text is enquiry evidence, never an open application. Country is not inferred from the domain. Live requests returning HTTP 520 remain unverified; the parser cannot claim live validation for blocked content. |
| Eventbrite | Supports scoped Event/Festival JSON-LD for event identity, dates and geography. Visitor ticket offers, including `InStock`, do not prove a trader application. Even a vendor-themed title remains conservative without specific application proof. |
| Marketspread | Distinguishes market/application routes from indexes. An authentication/login shell without retained single-event data cannot prove the event or availability. |
| Other domains | Requires scoped content and a matching single event before adding event evidence. Social, editorial, directory and ambiguous pages remain discovery only. The generic fallback never promotes visitor offers or contact links into open vendor applications. |

Search market/city is not a parser input and never supplies verified geography. Verification does not rewrite entity market, edition or identity keys. Country/edition mismatch quarantines the record. Contradictions with selected source-backed fields also prevent readiness.

Supported repairs use the existing additive proposal/authority/CAS model: vendor-form evidence has authority 95, generic extracted page evidence 60. Original receipts and source facts stay unchanged. A structured producer's authority-100 fact cannot be silently replaced by lower-authority verification; a disagreement remains visible and blocked until the producer supplies supported corrected evidence. Legacy quality holds remain immutable and effective while held facts are selected.

Readiness requires a current, revision-matched, verified proof as well as existing eligibility, identity-conflict and legacy-hold checks. SQL guards prevent a READY write without current proof. Enquiry availability is WATCH. Migration 0010 invalidates old derived READY claims and shadow projections without modifying evidence. The shadow API masks expired proof, and watch checks run daily. Customer publication and production traffic remain disabled.

The HTML reader is inert and bounded: scripts are parsed only as JSON data, never executed. Fetching accepts public HTTPS only, checks each redirect, sends no credentials, limits redirects/time/body size and respects source failures. There is no browser challenge bypass or paid-search fallback.

For reproducible measurement, run `operations/findpitches-v3/verify-quality.mjs` with secure credential/state paths and a private output directory containing `immutable-baseline-private.json`. It rechecks all 120 original legacy audit entities, all 10 original paid-pilot entities and four additional existing entities per source family. Its comparison preserves the original labels for unsafe records unless repaired by proof. Quarantine is not counted as improved customer usefulness. Results are descriptive Codex reviews, not independent human gold labels or population estimates.
