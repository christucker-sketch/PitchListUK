# Real-subscriber migration gate

Prepared by Codex for V3-010. This is read-only launch preparation, not authorization to import subscribers or enable live billing. V3-004 and V3-005 remain complete for their synthetic/TEST scope.

The [UK registry audit](../operations/findpitches-v3/reports/subscriber-coverage-2026-10-10.json), measured at 17:20:39 London on 10 October, found **57** distinct subscriber/customer/email records: cached active 27, trialing 6, cancelled 22 and past due 2. These are cached registry states, not verified paying-customer counts. Forty-nine have an exact vendor/customer/subscription profile binding; eight do not, including three cached-current records. Four cached-current subscriptions have scheduled cancellation.

[Read-only configuration evidence](../operations/findpitches-v3/reports/live-migration-readiness-2026-10-10.json), measured at **18:56:44 London**, confirms that the protected live UK Pages project has configured Stripe key, webhook, price and trial settings. They are opaque secret bindings: neither the actual default price nor a usable LIVE provider credential is available in this environment. No provider request, subscriber import, legacy write or message was made. Existing verified TEST billing is separate evidence.

Before approving any real cohort:

1. Obtain a fresh authenticated, read-only canonical snapshot of all selected customers and their paginated subscriptions. For the full current registry this means **57/57** owner, LIVE mode, product, price, quantity/currency/interval, status, cancellation, original trial history and authoritative paid-through-end validations. Retain private evidence and publish only counts/custody hashes. Missing dates must never be invented.
2. Resolve all **eight** vendor-binding exceptions using defensible original custody. Email equality is insufficient. Check provider-wide competing subscriptions for every owner, including the 49 currently exact registry bindings; no fallback new subscription or new trial is allowed.
3. Review an explicit actual legacy-price/product-to-V3 entitlement policy. Actual price variants remain unknown. Preserve paid-through access for the four scheduled cancellations; hold payment problems and unfamiliar products. The 22 cancelled and two past-due cached cases need canonical classification and a reviewed recovery/renewal policy, not ordinary new-customer Checkout.
4. Review a complete manifest for the exact authorized cohort. Accepted, held, duplicate, conflicting and no-match outcomes must sum to that cohort. Prove identity continuity, sign-in, original market/paid-through entitlement, no duplicate charge/trial, fail-closed provider errors and link redaction. The current operator adapter deliberately accepts synthetic TEST identities only; it cannot import this real registry.
5. Agree a reversible execution and rollback scope before enabling a live adapter. Stop on unknown ownership, unsupported prices, missing dates or competing subscriptions. Disable further imports/live Checkout and revoke affected V3 sessions if needed; retain original associations and append-only decisions. Never delete association history, silently rebind identity, cancel/recreate live subscriptions or alter their schedules as rollback.
