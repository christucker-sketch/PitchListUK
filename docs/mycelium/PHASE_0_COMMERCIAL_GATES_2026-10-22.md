Direction from Chris, 22 October 2026. Design requirement only; no permission to run, deploy or spend.

- Default incremental experimentation budget: **£0**. Use existing subscribed tools, current free allowances and existing hardware. No new paid subscriptions, API credits, cloud plans, or metered fallback without Chris explicitly approving the cost beforehand.
- Investigate a supported unattended Claude/Codex CLI collaboration using existing subscriptions first. Check each provider's current licensing and automation rules; do not assume browser or subscription credentials permit unrestricted unattended use. If not permitted, stop and report alternatives rather than circumvent limits.
- First milestone: a complete Codex → Claude review → Codex reconciliation handoff, logged end-to-end, no copy/paste by Chris, no production write rights. The prior £5 / six-call / 30-minute envelope is a proposed ceiling, **not permission to spend £5**. The first subscription-based test must incur £0 additional charges.
- Do not treat architecture documents, dialogue volume or candidate totals as delivery. Compare bounded Mycelium discovery trials with V3 control using source-proven distinct actionable event editions retained at 24h and 7d, withdrawals, duplication, human intervention, worker-hours and incremental costs. Agree pass/fail criteria before testing.
- Require explicit stage approval: unattended coordination proof; measurable discovery improvement; reliability/cost evidence; only then discussion of paid scaling. Pause or simplify if gates fail.
- Keep cloud-first coordination authority independent of BRIX machines and home broadband. Local workers may be replaceable capacity only.
- Before proposing any additional service spend, provide the observed bottleneck, no-cost options attempted, actual costs including recurring and variable charges, projected value, and an explicit approval request.
