## New FindPitches subscriptions are independent of legacy migration

There is **no technical requirement to complete the 57-row PitchList migration audit before brand-new FindPitches Checkout**. Ordinary Checkout creates its own Stripe customer with `findpitches_v3_customer_id`, keeps a V3-native ownership mapping, and canonically reads that customer's subscriptions. It does not query V1/V2 or the legacy registry. The legacy association branch runs only when a reviewed association exists.

Keep the production customer database initially empty of TEST fixtures and legacy imports; leave `/preview/subscribers/recognize` and synthetic provisioning unavailable in public mode. Do not find/attach a PitchList Stripe customer by email. A shared Stripe account does not require shared product, price, customer mapping, webhook or entitlement scope. A verified mailbox is the new account identity; the existing anti-repeat-trial guarantee is **per native account/canonical subscription history**, not a claim to identify the same human across multiple email addresses.

The existing migration gate remains separate: all 57 require authoritative LIVE owner/mode/product/price/end checks, eight binding exceptions and four cancellation-continuity cases. None is being imported here. The only current cross-product coupling found is **hostname hosting**, described below, not billing or evidence runtime.
